# Advertising account connections

These adapters connect accounts and execute explicit advertising actions from the app's authenticated REST/MCP callers. They list campaigns, create paused campaign containers, enable/pause configured campaigns, request spend reports, and upload conversion events. Enabling a campaign can start spending. An approved developer application and permission to the relevant business account are required; a normal social login does not establish advertising API access.

Register the exact callback `APP_ORIGIN/api/oauth/PROVIDER_ID/callback` with each developer application. For example, LinkedIn Campaign Manager uses `https://your-connector.example/api/oauth/linkedin-ads/callback`. Keep client secrets in the server environment; account access tokens are stored by the app in its encrypted credential store.

The resource list is a small verification preview: LinkedIn and X return at most 100 accounts, TikTok returns the first 50 Business Centers, Microsoft returns at most 100 customers/accounts. It is not a complete inventory or a reporting dashboard. A successful account-list request with an empty list means the API credential worked but returned no accessible resources.

| --- | --- | --- |

## LinkedIn Campaign Manager

For **“The redirect_uri does not match the registered value”**, follow the [LinkedIn redirect repair instructions](providers-linkedin.md). The member and advertising connections use different callback paths with the same saved Client ID. Register both URLs in that developer app when using both connectors.

Enable LinkedIn's **Advertising API** product and obtain the access tier required for your account. By default, the ads connection requests `r_ads rw_ads r_ads_reporting`. Add the Campaign Manager callback to the same client registration used by the LinkedIn profile adapter. Existing connections must reconnect to consent to expanded scopes. Set `LINKEDIN_ENABLE_CONVERSIONS=true` only after your app is approved for `rw_conversions`; this adds that scope to subsequent authorizations and enables the conversion action.

LinkedIn can invalidate previous tokens when the same app and member authorize a different scope set. If you use both LinkedIn Pages and Campaign Manager, enable **Use LinkedIn Pages and Ads together** (`LINKEDIN_COMBINE_SCOPES=true`) after confirming all displayed scopes are approved. Both cards then request the same permissions, including optional company, member-read, or conversion scopes selected in setup. Save all choices first, then update permissions on **both** connections without changing settings between them. This preserves saved accounts and credentials but requires fresh consent to replace already rejected tokens. See the [combined LinkedIn setup steps](providers-linkedin.md#keep-company-pages-and-campaign-manager-connected-together).

LinkedIn versions have a support lifecycle. `LINKEDIN_API_VERSION` must be a currently supported `YYYYMM` release. The pinned January 2026 default is explicit so upgrades can be reviewed instead of silently following the calendar. A release header alone does not confer Advertising API approval. Programmatic refresh is attempted only when LinkedIn actually provides a refresh token; otherwise reconnect when the access token expires.

Official references: [account search and management](https://learn.microsoft.com/en-us/linkedin/marketing/integrations/ads/account-structure/create-and-manage-accounts), [versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning), and the [LinkedIn-maintained Python client's `r_ads` finder example](https://github.com/linkedin-developers/linkedin-api-python-client#finder-request-example).

## Microsoft Advertising

Register a confidential **Web** application in Microsoft Entra ID that permits your Microsoft account type, add its callback, and obtain a Microsoft Advertising developer token. OAuth uses the `common` tenant, PKCE S256, and `https://ads.microsoft.com/msads.manage offline_access`. This scope covers account verification and the advertising actions documented below.

The developer token is separate from the OAuth client secret. Personal Microsoft sign-in or Microsoft Graph access alone is insufficient. The returned resources are the account IDs and customer roles the service supplies, with generic labels where account display names are unavailable. A customer role can grant access to all customer accounts without enumerating every account ID; this is not an exhaustive account search. Campaign and reporting actions require both the target advertising account ID and its managing customer ID.

Connection errors identify **authorization code exchange**, **token refresh**, or **account verification**. Entra failures include a numeric `AADSTS` code and an allowlisted OAuth error when Microsoft supplies them; Advertising REST faults include a numeric provider code. Raw response messages, credentials, URLs and tracking identifiers are never included. An HTTP 401 without a provider code identifies the failed stage but cannot establish which credential or account setting is wrong. Check a client secret only in the same Entra registration as the configured client ID; check the production developer token and the actual Advertising sign-in identity for account-verification failures. Personal and work identities with the same email can have different Advertising access. Do not reset unrelated connectors while investigating.

For `AADSTS650052`, follow Microsoft's [service-registration repair](https://learn.microsoft.com/en-us/advertising/guides/authentication-oauth-register?view=bingads-13#application-behavior). If Microsoft interrupts sign-in for security-information enrollment, complete that account's [Security info](https://mysignins.microsoft.com/security-info) registration before starting a fresh connection. Advertising REST errors follow the documented [AdApiFaultDetail](https://learn.microsoft.com/en-us/advertising/customer-management-service/adapifaultdetail?view=bingads-13) and [ApiFault](https://learn.microsoft.com/en-us/advertising/customer-management-service/apifault?view=bingads-13) contracts and [operation error codes](https://learn.microsoft.com/en-us/advertising/guides/operation-error-codes?view=bingads-13).

Official references: [GetUser REST contract](https://learn.microsoft.com/en-us/advertising/customer-management-service/getuser?view=bingads-13&tabs=prod&pivots=rest), [OAuth token exchange](https://learn.microsoft.com/en-us/advertising/guides/authentication-oauth-get-tokens?view=bingads-13), [developer tokens](https://learn.microsoft.com/en-us/advertising/guides/get-started?view=bingads-13#get-developer-token). Source contracts were checked in [MicrosoftDocs/Advertising GetUser](https://github.com/MicrosoftDocs/Advertising/blob/main/advertising/bingads-13/customer-management-service/getuser.md) and its [REST header definitions](https://github.com/MicrosoftDocs/Advertising/blob/main/advertising/bingads-13/customer-management-service/includes/request-header-rest.md).

## TikTok Business Manager

Create an app in **TikTok for Business**, obtain approval for the Business Center API, and authorize a user who can access the intended Business Center. These credentials are separate from the consumer TikTok Login Kit credentials. TikTok's consent page controls business permissions; the app cannot grant itself approval.

The callback contains `auth_code`, which is sent as JSON to `/open_api/v1.3/oauth2/access_token/`. API HTTP 200 responses are checked for `code: 0`; an error envelope is never treated as connected. The connection verifies the `bc_info` objects returned by `/bc/get/`. Standard API for Business tokens are reconnected if revoked or rejected; this adapter does not assume a consumer Login Kit or creator refresh endpoint applies to business access tokens.

Official references: [Business Center read API](https://business-api.tiktok.com/portal/docs?id=1737115687501826), [TikTok-maintained business SDK authentication contract](https://github.com/tiktok/tiktok-business-api-sdk/blob/main/js_sdk/docs/AuthenticationApi.md), and [Business Center SDK contract](https://github.com/tiktok/tiktok-business-api-sdk/blob/main/js_sdk/docs/BCApi.md#bcGet).

## X Business / Ads

Obtain approved **X Ads API** access and generate user-context OAuth 1.0a credentials for the intended account. Enter the **user access token** in the main credential field, and the **app consumer key**, **app consumer secret**, and **user access token secret** in the additional fields. These are stored encrypted together. An OAuth 2 bearer token from the social X connection is not interchangeable with this credential set.

This version uses developer-issued OAuth 1.0a credentials. Requests use HMAC-SHA1 signatures with a fresh nonce and timestamp, including all query parameters and URL-encoded form parameters. JSON bodies follow OAuth 1.0a's exclusion from the signature parameter set. Reconnect after rotating any credential. App approval, API tier, user roles, account availability, and version support are enforced by X. Mutations and conversions require appropriate advertiser roles such as AD_MANAGER or ACCOUNT_ADMIN.

Official references: [X Ads API](https://docs.x.com/x-ads-api/introduction), [accounts and users](https://docs.x.com/x-ads-api/accounts-and-users/overview), and the [X/Twitter-maintained SDK account model](https://github.com/twitterdev/twitter-python-ads-sdk/blob/master/twitter_ads/account.py). The older SDK demonstrates the same OAuth 1.0a account collection on the earlier `ads-api.twitter.com` hostname; the adapter targets the current X hostname and configurable version.

## Reddit Ads

Obtain Reddit Ads API approval and create a dedicated confidential OAuth web application for advertising. Reddit registers one redirect URI per app, so use distinct `REDDIT_ADS_CLIENT_ID` / `REDDIT_ADS_CLIENT_SECRET` credentials instead of the social Reddit client. Add the Reddit Ads callback to the app and set `REDDIT_ADS_ACCOUNT_ID` to the exact advertising account identifier from Reddit Ads. The consenting user must have access to that account. This is separate from a Reddit username and from the social Reddit connection. Configure a descriptive `REDDIT_USER_AGENT`, such as `web:your-connector:0.1.0 (by /u/yourname)`, for your installation.

The browser flow requests `adsread adsedit`, with `duration=permanent` for a refresh token. Reconnect existing read-only connections to grant editing access. Account verification reads a single campaign-list page and discards campaign data; the stored resource is the selected advertising account. It does not claim access to other ad accounts. Reddit can reject the scopes until the application has Ads API access. Refresh tokens are updated when Reddit rotates them. Reddit Conversions API uses a separate Events Manager access token: set `REDDIT_CONVERSIONS_TOKEN` on the server. The app never substitutes the advertising OAuth token for that token.

Official references: [Reddit Ads API v3](https://ads-api.reddit.com/docs/v3/) and [Reddit OAuth2](https://github.com/reddit-archive/reddit/wiki/OAuth2). The Ads docs could not be retrieved from the build environment, so the v3 campaign-list route, `adsread` scope, Basic token authentication, and response envelope were additionally checked against [Airbyte's maintained Reddit Ads connector](https://github.com/airbytehq/airbyte/blob/master/airbyte-integrations/connectors/source-reddit-ads/manifest.yaml). Live approved-account verification remains required after configuring credentials.

## Validation and network access

Tests use mocked contract responses to check authentication, Microsoft PKCE/refresh, GET/POST/PUT OAuth 1.0a signatures, paused creation defaults, report parameters, conversion schemas, partial failure handling, error redaction, and rejection of social-only responses. They cannot establish that your developer app has platform approval or a campaign has delivery eligibility. No live campaign launch, spend, or conversion upload was performed during implementation.

Server outbound HTTPS destinations are `www.linkedin.com`, `api.linkedin.com`, `login.microsoftonline.com`, `clientcenter.api.bingads.microsoft.com`, `campaign.api.bingads.microsoft.com`, `reporting.api.bingads.microsoft.com`, `business-api.tiktok.com`, `ads-api.x.com`, `www.reddit.com`, and `ads-api.reddit.com`. Browser authorization uses the corresponding official consent hosts. Microsoft report links are returned to the caller for direct download; the connector never fetches arbitrary report download URLs. Provider errors report safe permission/configuration guidance; raw provider error bodies and credentials are not returned to the caller.

## Available actions and delivery limits

All five providers implement `list-campaigns`, `create-campaign`, `set-campaign-status`, and `send-conversion`. LinkedIn, TikTok, X, and Reddit implement `read-spend`. Microsoft uses the two-step `request-spend-report` and `read-spend-report` actions. The action catalog returned by REST/MCP contains the exact field names, required identifiers, and input descriptions; callers should discover that catalog before executing an action. Writes require the application's explicit confirmation flag. These adapters do not generate creative content.

| Platform | Paused campaign creation | Launch/pause | Spend | Conversion upload |
| --- | --- | --- | --- | --- |
| LinkedIn | Sponsored-content `WEBSITE_VISITS`, CPC, daily budget/currency, existing campaign group, and caller-supplied official `targetingCriteria` JSON; English/US content locale | Scoped campaign partial update, `ACTIVE` or `PAUSED` | Daily local-currency report, first 100 rows, up to 31 days | Existing conversion rule, stable event ID, SHA-256 normalized email, actual event time, value/currency; restricted `rw_conversions` required |
| Microsoft | Search campaign, account-currency daily budget, required Microsoft timezone enum, `Paused` | REST Campaigns update, `Active` or `Paused` | Summary CSV report, account currency, up to 31 days; poll job then use temporary official ZIP download link | Existing OfflineConversionGoal name, original msclkid, UTC conversion time, value/currency; attribution window enforced by Microsoft |
| TikTok | `TRAFFIC` campaign, daily budget, `DISABLE`; supply advertiser ID, not Business Center ID | `ENABLE` or `DISABLE` | Daily auction-campaign account-currency report, first 100 rows, up to 31 days | Existing pixel code, standard web event, deduplication event ID, ttclid, time/value/currency via documented `pixel/track/`; optional `TIKTOK_EVENTS_ACCESS_TOKEN` overrides business OAuth for this request |
| X | Daily budget converted to account-currency micros, existing funding instrument, `PAUSED` | `ACTIVE` or `PAUSED` | UTC date-range totals, at most 7 days / 20 campaigns; `ALL_ON_TWITTER` placement only; local micros converted to currency units | Existing pixel and conversion event IDs, original twclid, deduplication conversion ID, ISO event time, `price_currency`, value; one processed conversion must be confirmed |
| Reddit | Traffic campaign, daily budget in micros, start time, `PAUSED` | `ACTIVE` or `PAUSED` | Daily GMT report, first 100 rows, up to 31 days; **SPEND is shown as the raw API reporting value because the current metric unit could not be authoritatively verified** | Website `PURCHASE`, original click ID, actual time within 7 days, value/currency; stable conversion ID is SHA-256 hashed; dedicated `REDDIT_CONVERSIONS_TOKEN` required |

Creating a campaign does **not** create every entity needed for delivery. Existing or separately configured ad groups/line items, targeting, approved creatives, conversion rules, business permissions, billing, and platform policy review are required. The connector can launch a fully configured existing campaign by changing its status; successful API acceptance is not proof that an ad is serving. A newly created paused container needs its remaining configuration in the platform or a later integration before it can deliver. Provider minimum budgets and funding limits apply.

Conversion requests are accepted for asynchronous matching and attribution. Retrying with a different event/deduplication ID can double-count events; preserve the same real event identifiers. HTTP success alone is not used for platforms with business error envelopes: Microsoft partial errors, TikTok nonzero codes, and X conversion processed counts are checked. Raw private provider error messages are discarded.

The spending previews are intentionally bounded and may omit additional result pages, placements, currencies, adjustments, or delayed data. In particular, X reporting only covers `ALL_ON_TWITTER`, and recent billed amounts can change. Microsoft links normally expire after five minutes; an empty successful report has no download. Reddit SPEND is not silently converted using a guessed unit.
